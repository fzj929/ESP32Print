# ESP32-S3 USB 打印网关开发计划

## 1. 文档目的

本文档作为后续开发、联调和验收的基线，定义 ESP32-S3 USB 打印网关的产品边界、
系统架构、接口契约、打印流程、安全要求、实施阶段和验收标准。

项目基于当前已经实机验证的 ESP32-S3 USB Host 打印程序继续开发。现有程序能够识别
HP DeskJet 2300（`03f0:3654`），并将目标驱动生成的 PRN 原样通过 USB Bulk OUT
发送给打印机。后续开发保留已经验证的 USB 传输逻辑，但将一次性、阻塞式的内嵌文件
打印流程重构为网络化、可重复接收作业的打印服务。

## 2. 已确认的产品需求

### 2.1 硬件条件

| 项目 | 参数 |
|---|---|
| 芯片 | ESP32-S3，双核 240 MHz，revision 0.02 |
| SPI Flash | 外置 16 MB，80 MHz，QIO |
| PSRAM | 外置 8 MB |
| 内部 RAM | 约 379 KB，总可用量会随 Wi-Fi、USB、TLS 等组件减少 |
| 外部存储 | 无 SD 卡 |
| 打印机连接 | ESP32-S3 原生 USB Host |
| Wi-Fi | 2.4 GHz SoftAP |
| 恢复输入 | 正式产品增加一个带硬件下拉的非启动绑带 GPIO，可接专用按键或跳线 |

“Embedded Flash/PSRAM: No”仅表示芯片封装内部没有集成存储，不否定板载外置
16 MB Flash 和 8 MB PSRAM。开发时仍须通过启动日志确认 PSRAM 已正确初始化并加入
能力堆。

### 2.2 网络参数

| 项目 | 初始值 |
|---|---|
| 工作模式 | Wi-Fi SoftAP |
| SSID | `mybips.com` |
| Wi-Fi 密码 | `cCwX6goRgJ` |
| 板卡 IP | `192.168.188.1` |
| 子网掩码 | `255.255.255.0` |
| DHCP | 开启，由板卡为客户端自动分配地址 |
| 建议地址池 | `192.168.188.100`～`192.168.188.200` |

首次打开维护页面并验证初始管理密码后，初始化流程必须同时设置新管理密码、
本机 SSID 和本机 Wi-Fi 密码。多台板卡应配置不同 SSID（建议包含场地或打印机编号），
使用户可以明确连接目标打印机对应的板卡。配置持久化到 NVS，成功后设备重启，
客户端使用新凭据重连；板卡 IP 保持 `192.168.188.1`。后续管理员可在打印机空闲时
修改热点配置，修改时不得中断活动作业。查询接口可返回 SSID，不得返回 Wi-Fi 密码。

SSID 看起来像域名，但默认不代表浏览器能够解析 `mybips.com`。第一版以
`192.168.188.1` 为访问地址；本地域名或 captive portal 可作为后续增强功能。

### 2.3 用户和打印规则

1. 允许多个手机或电脑同时连接热点、登录、查询板卡和打印机信息。
2. 同一时刻只允许一个活动打印会话占用打印机。
3. 创建会话时客户端必须声明总页数。
4. PRN 按页生成、按页上传，每页约 1 MB，协议硬上限为 2 MiB（2,097,152 字节）。
5. 页码必须从 1 开始连续提交，不能越页、倒序或并发提交。
6. 一页完整上传并校验后立即送往打印机；上一页未结束前不能上传下一页。
7. 当前会话全部页面结束、主动取消或安全超时释放后，第二个用户才能创建打印会话。
8. 其他用户在打印机被占用期间仍可查询状态，但打印请求返回“打印机已被占用”。
9. 第一版总页数范围为 1～999；超过范围时拒绝创建会话。

### 2.4 身份认证

- 初始管理密码为 `mybips.com`。
- 首次设置未完成时必须修改密码，未修改前禁止创建会话、上传页面和打印。
- 密码不得以明文保存。
- 登录成功后使用有有效期的 Bearer Token 调用接口。
- 修改密码后使已有 Token 全部失效，并要求使用新密码重新登录。
- 正式产品必须提供实体恢复/初始化机制，不能仅依靠远程接口恢复管理密码。

### 2.5 设备唯一编号

- 每块板卡具有一个服务器分配的不可变 `device_id`。
- `device_id` 在量产烧录/安全配置工序中通过参数传给制造工具。
- 制造工具将其一次性写入预留 eFuse 用户数据区域，读回验证后永久写保护。
- 运行固件只具备读取能力，不提供任何修改 `device_id` 的本地或网络接口。
- 密码恢复、恢复设置、OTA 和更换打印机都不能改变 `device_id`。
- 服务器显示名称、安装位置和客户资产编号属于服务器侧可变元数据，不写入不可变 ID。
- ESP32-S3 出厂 MAC 作为辅助审计字段，不直接替代服务器分配的 `device_id`。
- 每台设备同时生成独立的高熵恢复码，印在设备标签或随设备密封交付卡上；恢复码是秘密，
  与公开的 `device_id` 不同。

`device_id` 使用 128 位二进制值，接口和服务器统一采用小写 UUID 文本格式，例如
`018f5f2e-7b6a-7c10-9a31-4f66c2c8a901`。制造系统必须在烧写前向服务器预留该 ID 并检查
唯一性，不允许操作员任意重复使用编号。

### 2.6 打印机兼容目标

第一阶段通用化目标为：

- 自动发现 USB Printer Class 接口；
- 支持 Printer Class Protocol 1（单向）和 Protocol 2（双向）；
- 动态识别 Interface、Alternate Setting、Bulk OUT 和可选 Bulk IN；
- 读取 USB Device Descriptor、字符串描述符和 IEEE 1284 Device ID；
- 由服务器根据打印机身份和命令集选择相应驱动；
- PRN 必须由当前目标打印机对应的驱动生成。

以下类型不纳入第一阶段的兼容承诺：

- IEEE 1284.4 Protocol 3；
- IPP-over-USB；
- 厂商私有 USB 打印协议；
- 仅支持网络打印、不提供标准 USB Printer Class 的设备；
- 将一个型号的驱动输出发送给不兼容的另一型号。

对外兼容性表述应为“支持经过验证的标准 USB Printer Class Protocol 1/2 打印机”，
不能笼统宣称兼容所有或绝大多数打印机。每个正式支持型号必须完成实机测试并加入验证表。

打印机能力分为三个等级，接口和产品资料不得混用：

| 等级 | 含义 | 是否允许正式自动打印 |
|---|---|---|
| `discovered` | 能完成 USB 枚举并读取部分身份信息 | 否 |
| `transport_compatible` | 找到可用的 Protocol 1/2 接口和 Bulk OUT | 默认否，仅限受控测试 |
| `verified_supported` | 使用指定驱动和打印语言完成实机及故障测试 | 是 |

## 3. 核心技术决策

### 3.1 单页接收方式

第一版采用“HTTP 分块接收、PSRAM 整页暂存、完整校验后发送 USB”的方式：

```text
客户端按块上传页面
        │
        ▼
HTTP Server（边收边计算 SHA-256）
        │
        ▼
PSRAM 页面缓冲（最大 2 MiB）
        │ 上传长度和摘要校验通过
        ▼
USB 打印任务（分块 Bulk OUT）
        │
        ▼
打印机
```

这满足 HTTP 流式接收要求：HTTP 处理过程不要求把请求体放入内部 RAM，而是循环读取
小块数据写入 PSRAM。第一版不采用“HTTP 尚未接收完整就立即送 USB”的直通模式，原因是
直通模式无法在打印前验证完整文件，网络中断时容易产生不可恢复的半页作业。

### 3.2 容量约束

- 单页协议硬限制：2 MiB。
- 同时缓存页面数：1 页。
- 建议 HTTP 接收块：16～32 KiB。
- 建议 USB 提交块：1～8 KiB，最终值通过实测确定。
- 页面缓冲使用 `MALLOC_CAP_SPIRAM` 明确分配。
- USB DMA、任务栈和必须位于内部 RAM 的对象不得错误放入 PSRAM。
- 启动和运行状态中记录 PSRAM 总量、剩余量和最大连续块。

PSRAM 标称容量不是可全部占用的应用容量。2 MiB 是正式产品上限；若未来要提高到
4 MiB，必须先完成 Wi-Fi、HTTPS、USB 并发压力测试和长时间碎片测试。

### 3.3 Flash 使用策略

普通 PRN 页面默认不写入 Flash，以减少大量页面带来的擦写磨损。Flash 用于：

- 双 OTA 固件槽；
- NVS 配置和密码摘要；
- TLS 证书及设备身份材料；
- 内嵌管理页面；
- 少量诊断信息和经过控制的持久化状态。

需要新增自定义 16 MB 分区表。初始规划为两个约 3.5～4 MB 的 OTA 应用槽，剩余空间
分配给 NVS、OTA Data、安全数据、诊断和必要的文件系统。最终尺寸在加入 Wi-Fi、HTTPS、
页面和通用打印支持后，根据实际固件大小确定并保留升级余量。

### 3.4 不可变设备身份

`device_id` 保存到专门预留、保持可读且写保护的 eFuse 用户数据区域。不能只把编号写进
普通 NVS、文件系统、编译宏或 OTA 分区，因为这些位置可被擦除、重新烧录或软件改写。

eFuse 分配必须与 Secure Boot、Flash Encryption 和设备密钥统一规划。编号区域独占一个
经过确认可用于用户数据的块，不与 Custom MAC、密钥或其他后续可能写入的字段混用；最终
块号在量产 eFuse 分配表评审后确定。ESP32-S3 eFuse 是一次性可编程资源，写保护操作不可逆，
所有生产命令必须先在虚拟 eFuse 和专用样机上验证。

建议在 32 字节区域中保存：

| 字段 | 长度 | 说明 |
|---|---:|---|
| Magic | 4 字节 | 固定产品标识 |
| Schema Version | 1 字节 | 身份结构版本 |
| Reserved | 3 字节 | 对齐和未来兼容 |
| Device ID | 16 字节 | 服务器分配的 128 位 UUID |
| CRC32 | 4 字节 | 检测生产写入或读取错误 |
| Reserved | 4 字节 | 必须按规定值一次性写入 |

量产工序必须按以下顺序执行：

1. 制造工具接收强制参数 `--device-id <uuid>`，验证格式；
2. 查询服务器并预留 ID，拒绝已经激活或被其他板卡占用的 ID，同时生成一次性展示的
   128 位随机恢复码；
3. 读取目标 eFuse 区域，确认空白、可读、未写保护且分配正确；
4. 生成完整 32 字节映像，一次性烧写；
5. 读回并校验 Magic、版本、UUID 和 CRC32；
6. 永久写保护编号区域，但保持可读；
7. 再次读回并确认内容以及保护状态；
8. 为恢复码生成 16 字节随机盐，使用版本化参数计算 32 字节
   PBKDF2-HMAC-SHA256 验证值；把 KDF 版本、迭代次数、盐和验证值写入受保护的
   `device_security` NVS 命名空间，读回结构并通过一次本机验证自检，但不输出恢复码或验证值；
9. 将 `device_id`、出厂 MAC、设备证书公钥指纹、芯片 revision、生产批次和时间登记到服务器；
   恢复码只保存加盐验证值或受严格访问控制的加密副本，不能进入普通生产日志；
10. 任一步骤不一致时隔离该板卡，不允许通过再次强写修补后流入成品。

固件启动时读取并校验编号内容、CRC 和写保护状态。编号缺失、CRC 错误或目标区域仍可写时
都进入 `unprovisioned` 故障状态：允许本地诊断，不允许创建打印会话或注册到生产服务器。
官方工具支持烧写任意 eFuse 块数据和永久写保护，但操作只能把位从 0 烧成 1，不能撤销，
因此量产脚本必须默认禁止强制覆盖参数。

每台设备的 TLS 证书必须把同一个 `device_id` 放入经过定义的 Subject Alternative Name 或
专用证书扩展。固件启动时校验证书身份与 eFuse ID 一致；服务器建立 HTTPS 连接时验证产品
CA、证书中的 ID 和制造登记的公钥指纹三者一致。JSON 中的 `device_id` 只用于路由和日志，
不能单独作为设备身份认证依据。

### 3.5 “一页打印完成”的定义

标准 USB Printer Class 通常只能确认某页的全部字节已由 USB Host 栈成功提交给设备，
不能通用、可靠地确认纸张已经完成机械出纸。因此第一版统一使用以下状态定义：

- `receiving`：正在接收页面；
- `validated`：页面接收完整且校验成功；
- `sending_usb`：正在通过 Bulk OUT 发送；
- `usb_delivered`：本页全部字节已被 USB 传输层接收；
- `failed_before_usb`：能够证明尚未向打印机发送任何字节，可以安全重试；
- `failed_unknown`：可能已有部分字节进入打印机，或无法证明发送字节数为零，禁止自动重试；
- `mechanical_completion: unknown`：无法确认机械出纸完成。

系统以 `usb_delivered` 作为允许当前会话提交下一页的条件。若某些型号能够通过厂商协议
准确报告机械完成，可在对应打印机适配器中扩展，但不能作为通用能力假设。

最后一页达到 `usb_delivered` 后，会话自动进入 `completed` 并立即释放打印锁；完成记录
在 RAM 中保留 10 分钟供查询和幂等响应，随后清理。设备重启后不承诺保留打印结果，
客户端不得在重启后根据旧请求自动重印结果未知的页面。

## 4. 软件架构

建议将现有单文件程序拆分为以下组件：

| 组件 | 职责 |
|---|---|
| `network_service` | SoftAP、静态 IP、DHCP、连接事件 |
| `http_api` | URI 注册、JSON 响应、请求长度和超时控制 |
| `auth_service` | 密码验证、首次改密、Token、限速和权限 |
| `web_ui` | 内嵌登录、状态、打印和改密页面 |
| `usb_printer_transport` | USB Host 生命周期、接口声明、控制和 Bulk 传输 |
| `printer_discovery` | 描述符遍历、字符串读取、`GET_DEVICE_ID` 和能力解析 |
| `printer_registry` | 打印机指纹、已验证型号和兼容配置 |
| `print_session` | 单会话互斥、所有者、页码、租约和状态机 |
| `page_receiver` | 分块接收、PSRAM 缓冲、长度限制和 SHA-256 |
| `print_worker` | 串行消费页面并调用 USB 传输层 |
| `device_identity` | 读取并校验 eFuse `device_id`，提供不可变设备身份 |
| `device_config` | NVS 配置、固件版本、首次设置和认证恢复状态 |
| `status_led` | 将网络、会话和打印状态映射到 RGB 灯 |

### 4.1 并发原则

- USB Host 由一个专用打印任务独占。
- HTTP URI Handler 不直接并发调用 USB API。
- HTTP 与打印任务通过队列、事件组或任务通知传递命令。
- 同一时刻最多存在一个页面缓冲和一个打印会话。
- 查询接口不能阻塞正在进行的页面传输。
- USB 状态控制请求和 Bulk OUT 必须在传输层统一串行调度。

当前 `open_and_print()`、`stop_job()` 和无限监控循环需要改造成可返回、可恢复的状态机。
单次作业失败不得让整个固件永久停在死循环中。

## 5. 服务器端标准流程

```text
1. 连接 Wi-Fi 热点并自动获取 IP
2. 登录；首次设置未完成时同时修改管理密码与本机热点名称、密码，重连新热点
3. 查询 /printer/info
4. 服务器按打印机指纹选择驱动
5. 查询 /printer/status，确认基本就绪
6. 创建打印会话，声明总页数和预期打印机配置
7. 用目标驱动生成第 1 页 PRN
8. 上传第 1 页，等待 usb_delivered
9. 依次生成并上传后续页面
10. 最后一页成功后结束会话并释放打印机
```

服务器不能仅使用打印机产品名称匹配驱动。建议优先级为：

1. 已绑定的设备序列号；
2. VID、PID 精确匹配；
3. IEEE 1284 `MFG`、`MDL` 精确匹配；
4. `CMD` 打印语言能力匹配；
5. 无可靠匹配时拒绝自动打印并要求人工配置。

## 6. HTTP API 设计

### 6.1 通用规则

- API 前缀：`/api/v1`。
- 除登录和静态页面外，接口必须携带 `Authorization: Bearer <token>`。
- 普通请求和所有响应使用 JSON。
- 页面正文使用 `application/octet-stream`。
- 页面上传必须包含 `Content-Length`，且不得超过 2,097,152 字节。
- 生产模式要求页面携带 SHA-256。
- 身份校验通过时，每个响应包含不可变 `device_id` 和 `request_id`，便于服务器关联板卡及
  对应设备日志。设备处于 `unprovisioned` 时诊断响应必须使用 `device_id: null`，且不得
  返回 CRC 或写保护未通过的原始编号。
- 不向响应或日志输出密码、Token、页面正文及完整 PRN 内容。

成功响应：

```json
{
  "ok": true,
  "device_id": "018f5f2e-7b6a-7c10-9a31-4f66c2c8a901",
  "request_id": "req-001",
  "data": {}
}
```

失败响应：

```json
{
  "ok": false,
  "device_id": "018f5f2e-7b6a-7c10-9a31-4f66c2c8a901",
  "request_id": "req-001",
  "error": {
    "code": "PRINTER_RESERVED",
    "message": "打印机正在被其他会话使用"
  }
}
```

### 6.2 认证接口

#### `POST /api/v1/auth/login`

请求：

```json
{
  "password": "mybips.com"
}
```

首次设置未完成时登录返回受限 Token：

```json
{
  "ok": true,
  "device_id": "018f5f2e-7b6a-7c10-9a31-4f66c2c8a901",
  "request_id": "req-001",
  "data": {
    "access_token": "...",
    "expires_in": 1800,
    "must_change_password": true,
    "recovery_required": true,
    "recovery_challenge": "<随机一次性challenge>",
    "recovery_expires_in": 600
  }
}
```

首次改密 Token 只允许访问板卡状态、打印机信息、恢复认领、修改密码和注销接口。密码长度第一版
限制为 8～64 个 UTF-8 字节。两个客户端并发修改时，NVS 更新采用互斥和原子状态检查，
只有第一个基于当前密码成功提交的请求生效，后续请求返回认证状态已变化。

#### `POST /api/v1/auth/recovery/claim`

仅在首次出厂设置或实体认证恢复后的 10 分钟窗口内可用。请求包含
`recovery_challenge` 和设备标签上的 `recovery_code`。验证成功后返回一次性的
`recovery_claim_id`，并把它绑定到当前 `device_id`、`auth_session_id` 和 challenge；同一
窗口只能有一个成功认领者。失败请求限速且不得泄露是编号、challenge 还是恢复码错误。

`recovery_claim_id` 只保存在 RAM，有效期为 5 分钟且不能超过所属 challenge 的剩余时间。
同一 `auth_session_id` 的 Token 刷新不改变 claim；注销、认证会话硬过期、设备重启、claim
超时或新密码保存成功都会立即使其失效。新密码仅因格式不合格而被拒绝时，可在剩余有效期
内修正后再次提交；其他认证或绑定校验失败会吊销 claim。恢复未完成时设备重启会生成新的
challenge，用户必须重新使用恢复码认领。

#### `PUT /api/v1/auth/password`

正常改密请求包含当前密码和新密码。首次出厂设置或认证恢复后的改密还必须携带当前
`auth_session_id` 对应的 `recovery_claim_id`。成功后吊销设备内全部活动 Token，并将
`must_change_password` 设置为 `false`；claim 同时作废。

#### `POST /api/v1/auth/logout`

立即吊销当前 Token。

#### `POST /api/v1/auth/refresh`

在当前 Token 有效时换取新 Token，并保留同一个 `auth_session_id`。Token 空闲有效期为
30 分钟，认证请求会刷新空闲时间；单个认证会话最长为 24 小时，达到上限后必须重新登录。
刷新不会改变打印会话所有权。Token 已过期时不能刷新。

### 6.3 板卡接口

#### `GET /api/v1/device/status`

至少返回：

- eFuse `device_id`、出厂 MAC、固件版本和构建版本；
- 设备身份结构版本、CRC 校验结果和 `provisioned` 状态；
- 设备证书公钥指纹及其与 `device_id` 的绑定校验结果；
- 运行时间、复位原因；
- SoftAP IP、已连接客户端数；
- 内部 RAM 和 PSRAM 的总量、剩余量、低水位和最大连续块；
- Flash 容量、OTA 槽和当前启动分区；
- 当前打印会话摘要；
- USB 打印机是否连接。

#### `POST /api/v1/device/reboot`

仅允许已完成首次改密的管理员调用。接口先返回 JSON，再延迟短时间执行重启。
打印或上传过程中默认拒绝重启；如以后支持强制重启，必须使用独立的显式参数和权限。

### 6.4 打印机信息接口

    "identity": {

      "product_id": "3654",

      "product": "HP DeskJet 2300 series",

    },
    "usb": {
      "interface_number": 1,
      "alternate_setting": 0,
      "interface_class": 7,

### 6.5 打印机状态接口

#### `GET /api/v1/printer/status`

返回连接、基本端口状态和当前作业状态：

```json
{
  "ok": true,
  "device_id": "018f5f2e-7b6a-7c10-9a31-4f66c2c8a901",
  "request_id": "req-001",
  "data": {
    "connected": true,
    "readiness": "ready",
    "paper_empty": false,
    "selected": true,
    "reported_error": false,
    "raw_port_status": "0x18",
    "session_state": "waiting_next_page",
    "page_state": "usb_delivered",

  }

```

标准端口状态信息有限。墨量、卡纸详情和机械完成状态只有在具体型号支持并完成适配后
才能返回；未知值必须明确标为 `unknown`。`readiness` 使用 `ready`、`not_ready`、
`unknown` 三态，不能把状态请求失败当成“就绪”。对 `verified_supported` 型号由本机
注册表定义未知状态下是否允许发送；其他型号在状态未知时默认拒绝自动打印。

### 6.6 打印会话接口

#### `POST /api/v1/print-sessions`

请求示例：

```json
{
  "job_id": "server-job-20260918-001",
  "total_pages": 8,
  "printer_profile": "usb:03f0:3654:pcl3gui",
  "printer_fingerprint": {
    "vendor_id": "03f0",
    "product_id": "3654",
    "serial_number": "CN12345678"
  },
  "driver": {
    "driver_id": "hp-dj-2300-pcl3",
    "driver_version": "server-defined",
    "pdl": "PCL3GUI",
    "settings_sha256": "<64位十六进制摘要>"
  }
}
```

成功后生成不可预测的 `session_id`，锁定当前打印机身份并返回下一页页码和租约。
打印机已被占用时返回 HTTP 409 和 `PRINTER_RESERVED`。

会话绑定到当前登录产生的稳定 `auth_session_id`，而不是 Bearer Token 字符串本身。
访问 Token 在有效期内可通过刷新接口轮换，但必须仍引用同一 `auth_session_id`。Token
过期、注销或改密不会在 `receiving`/`printing` 期间释放打印锁。所有者失去凭据后只能
等待安全租约到期，或由具有有效 Token 的管理员安全取消。

量产固件创建会话时要求当前打印机为 `verified_supported`，否则返回
`PRINTER_NOT_VERIFIED`。研发固件可以通过编译期开关允许 `transport_compatible` 设备进入
受控测试；该开关在量产配置中必须关闭，不能通过普通 HTTP 参数绕过。

板卡根据本地验证注册表核对 `printer_profile`、VID/PID 和 `pdl`；`driver_id`、版本及
`settings_sha256` 用于日志追踪和服务器幂等，板卡不解析厂商驱动设置本身。语言或 profile
不匹配时拒绝创建会话。

#### `POST /api/v1/print-sessions/{session_id}/heartbeat`

延长等待下一页期间的会话租约。HTTP keep-alive 或单个 TCP 连接不能代替会话租约。

#### `POST /api/v1/print-sessions/{session_id}/pages/{page_number}`

请求头至少包含：

```http
Content-Type: application/octet-stream
Content-Length: 1048576
X-Page-SHA256: <64位十六进制摘要>
Authorization: Bearer <token>
```

检查顺序：

1. Token 和会话所有者匹配；
2. 打印机会话仍锁定到同一设备指纹；
3. 先查询 `job_id + page_number + SHA-256` 幂等键和当前页接收槽；命中既有、接收中或
   打印中记录时直接按下述幂等规则响应，不继续分配缓冲；
4. 未命中幂等记录时，检查页码等于 `next_page`；
5. 长度大于 0 且不超过 2 MiB；
6. 原子占用当前页接收槽并分配 PSRAM 页面缓冲；
7. 请求体完整接收；
8. 实际长度和 SHA-256 校验通过；
9. 打印机状态允许发送；
10. 将页面加入唯一打印任务并返回 HTTP 202、当前状态和查询地址。

上传接口不保持 HTTP 请求直到 USB 打印结束。页面完整接收、校验并成功排入唯一打印任务后
返回 `202 Accepted`；后台立即开始 USB 发送。客户端轮询会话状态，只有看到本页
`usb_delivered` 和新的 `next_page` 后才能上传下一页。若过早上传，返回 HTTP 409 和
`PAGE_NOT_READY`。这样可避免打印机长时间 NAK 导致客户端超时后误判和重传。

页面已经 `usb_delivered` 后，重复提交相同作业号、页码和摘要时，不得再次打印，
应返回既有结果。幂等键由 `job_id + page_number + SHA-256` 组成，在活动会话及其完成记录
10 分钟保留期内有效。若 USB 失败发生在可能已经提交部分字节之后，返回
`PRINT_RESULT_UNKNOWN`，禁止自动重试。

同页并发和重试必须原子处理：第一个通过 Header 校验的请求先占用当前页接收槽；接收尚未
完成时，相同幂等键返回 `UPLOAD_IN_PROGRESS`，不同摘要返回 `PAGE_CONFLICT`。页面已经排队
或正在 USB 发送时，相同幂等键返回现有 HTTP 202 状态且不得二次入队，不同摘要仍返回
`PAGE_CONFLICT`。只有在请求体未完整接收且确认尚未进入 USB 队列时，才清除接收槽并允许
相同幂等键重新上传。

#### `GET /api/v1/print-sessions/{session_id}`

返回会话所有者、总页数、下一页、当前页状态、错误、创建时间和租约剩余时间。

#### `DELETE /api/v1/print-sessions/{session_id}`

只允许会话所有者或具有有效 Token 的管理员取消。尚未进入 USB 发送时可以立即取消并释放锁；
正在 USB 发送时只记录取消意图，不强制复用传输资源，等待当前传输完成或失败后再释放。
若传输结果不确定，会话进入 `failed_unknown` 并保持打印锁，禁止自动重印或自动交给下一用户。

#### `POST /api/v1/print-sessions/{session_id}/resolve-unknown`

仅允许具有有效 Token 的管理员在检查打印机后调用。请求动作固定为
`release_without_retry`；板卡停止并重新初始化 USB 端点，保留结果未知记录，然后释放打印锁。
打印机物理断开并重新枚举也可结束锁定，但旧页面仍保持结果未知。该接口不会重新打印页面。

## 7. 状态机

### 7.1 打印机会话状态

```text
idle
  └─ create ─> reserved
                  ├─ upload ─> receiving
                  │              ├─ invalid ─> waiting_retry
                  │              └─ valid ─> printing
                  │                            ├─ delivered ─> waiting_next_page
                  │                            ├─ zero bytes proven ─> failed_before_usb ─> waiting_retry
                  │                            └─ partial/uncertain ─> failed_unknown
                  ├─ last page delivered ─> completed + release lock
                  ├─ safe timeout/cancel ─> cancelled ─> idle
                  └─ printer changed/disconnected ─> failed ─> idle/manual_confirm
```

### 7.2 会话租约

- `reserved` 或 `waiting_next_page` 状态使用 120 秒租约，两种状态都允许 heartbeat 续租。
- 合法心跳或下一页上传可续租。
- `receiving` 和 `printing` 期间不得因普通租约到期把打印机分配给第二个用户。
- HTTP 接收断开且尚未发送 USB 时可安全丢弃当前页面。
- USB 已开始发送后断开连接，继续完成当前传输并记录结果，不允许第二个会话插入。
- 每次合法心跳或状态推进后重置租约。租约到期只在没有接收或 USB 传输活动时执行取消和
  释放。`failed_unknown` 必须先停止端点复用并完成错误收敛，不能在超时瞬间把打印机
  交给另一个会话。
- 页面接收空闲超时为 30 秒、单页接收总超时为 120 秒；超时且未入 USB 队列时安全丢弃。
- 单页 USB 发送总超时初始值为 180 秒；超时进入 `failed_unknown`，必须通过物理重连或
  `resolve-unknown` 明确处理，因此不存在异常后无限等待且无解除手段的状态。

## 8. 打印机发现与驱动匹配

### 8.1 枚举流程

1. 读取 Device Descriptor 和可用字符串描述符；
2. 遍历活动 Configuration 中所有 Interface/Alternate Setting；
3. 查找 Class `0x07`、Subclass `0x01`；
4. 记录 Protocol；
5. 在对应接口下查找 Bulk OUT 和可选 Bulk IN；
6. 声明选中的接口；
7. 调用 `GET_DEVICE_ID` 并按 IEEE 1284 格式解析；
8. 调用 `GET_PORT_STATUS` 获取基础状态；
9. 生成稳定的打印机指纹；
10. 与本机已验证注册表匹配并给出三档能力等级。

服务器维护“打印机指纹/能力 → 驱动、驱动版本、打印语言和默认选项”的权威映射；板卡
返回的 `profile_id` 只是能力和实机验证结果，不替服务器决定驱动。会话创建时服务器提交
所选 profile、驱动标识、PDL 和设置摘要，板卡验证 profile 与 PDL 是否和当前打印机注册
信息一致，并记录其余字段用于追踪。人工覆盖规则
保存在服务器端，未经实机验证时不得把设备标为 `verified_supported`。

### 8.2 会话期间设备变化

创建会话时保存打印机身份快照。以下任一项变化时停止接收后续页面：

- USB 设备断开并重新连接；
- VID/PID 变化；
- 有效序列号变化；
- 选中的打印接口或 Protocol 变化；
- 服务器声明的 `printer_profile` 与当前能力不匹配。

相同型号但无序列号的设备重新连接后也不能自动假定为同一台，应要求服务器重新查询和
创建会话。

## 9. 安全设计

### 9.1 密码和 Token

- 使用随机盐和经过评审的密码派生算法保存密码验证值，不保存明文密码。
- Token 使用硬件随机数生成，具备过期时间和权限范围。
- Token 默认只保存在 RAM，重启后失效；Token 内部引用稳定的 `auth_session_id`。
- 登录失败按来源限速，并限制连续失败次数。
- 日志不得记录密码、Token 或完整 Authorization 头。
- 首次设置完成前只授予受限权限。

所有量产设备使用相同初始密码存在“抢先初始化”风险。当前基线保留 `mybips.com` 作为
初始密码，但首次设置和认证恢复后的改密必须同时通过每机唯一恢复码，并绑定一次性 challenge
和 `auth_session_id`；统一初始密码本身不能取得设备所有权。

### 9.2 传输安全

研发阶段可以先使用 HTTP 完成功能联调。正式产品需评估并实现 HTTPS，避免同一热点内的
其他客户端截获管理密码、Token 或文档内容。服务器客户端应采用证书固定或受控 CA；浏览器
管理页面的证书安装和首次信任流程需要在产品化阶段确定。

### 9.3 固件安全

量产版本必须启用：

- Secure Boot v2；
- Flash Encryption Release 模式；
- 受保护的 NVS 和设备密钥；
- 签名 OTA；
- 关闭或限制量产设备调试和下载能力。

这些设置涉及不可逆 eFuse 操作，必须先在专用样机验证制造、升级和恢复流程，不能直接在
普通开发板上盲目启用。

### 9.4 输入校验

- 限制 Header 长度、JSON 长度、URI 长度和正文长度；
- 拒绝未知或重复的关键 Header；
- 页码和总页数使用有上限的整数；
- 作业号、会话号只接受限定字符集和长度；
- SHA-256 必须严格为 64 位十六进制；
- 拒绝长度为零、超长、短传输和校验失败的页面；
- 禁止通过文件名构造本地路径；第一版页面不落盘；
- 配置合理的接收、发送和空闲超时。

### 9.5 忘记密码与启动恢复输入

正式产品使用专用 GPIO 执行“认证恢复”，不提供无需当前密码即可调用的远程恢复接口。
GPIO 必须使用非启动绑带引脚并配置硬件下拉，默认稳定为低电平；用户通过按键或跳线在上电
前将其拉高。最终 GPIO、电平和上下拉参数以硬件原理图评审为准。

恢复检测和设置流程：

1. 用户断电，将恢复 GPIO 保持为高电平，然后重新上电；
2. 固件进入应用后、启动 Wi-Fi 和 HTTP 服务前，以固定间隔连续采样约 2 秒；只有整个确认
   窗口持续为高电平才触发恢复，单次采样或上电毛刺不能触发；
3. 板卡清除管理认证及 SoftAP 凭据，恢复初始热点，以便遗忘 Wi-Fi 密码后仍可进入页面；
   设置 `must_change_password=true`，递增 `credential_reset_counter`，并清除 RAM 中的
   Token、认证会话和打印会话；
4. 状态灯显示恢复成功，固件等待 GPIO 回到低电平；GPIO 未释放时不启动热点和管理页面，
   避免按键卡住或跳线未取下时反复进入设置；
5. GPIO 回到低电平后启动初始 `mybips.com` SoftAP 和网页，管理密码恢复为
   `mybips.com`，但仍处于首次设置未完成状态，打印接口保持禁用；
6. 板卡生成随机 `recovery_challenge`，恢复设置窗口持续 10 分钟；
7. 用户用初始密码登录后输入设备标签/交付卡上的唯一恢复码；客户端将恢复码和 challenge
   通过 HTTPS 提交到恢复认领接口；
8. 验证成功后，板卡把本次恢复权原子绑定到该请求的 `auth_session_id`，其他客户端即使
   知道统一初始密码也不能设置新密码；
9. 只有该认证会话可以提交并确认两次一致的新密码。保存成功后使 challenge 和恢复码验证
   上下文失效、关闭恢复设置窗口、吊销临时 Token，并要求使用新密码重新登录。

首次出厂设置同样要求唯一恢复码，避免所有设备使用统一初始密码时被附近用户抢先初始化。
恢复码至少具有 128 位随机强度；设备只保存加盐后的验证值或专用验证密钥，存放在受 Flash
Encryption 保护且不会被认证恢复清除的安全命名空间。恢复码连续失败必须限速，任何成功的
challenge 只能使用一次，并严格绑定 `device_id + auth_session_id + recovery_challenge`。

恢复只在一次全新启动的初始化阶段检测，因此不会在运行中按键误触、中断 USB 作业或产生
半页打印。掉电不得造成密码摘要和 `must_change_password` 状态各写一半，认证恢复必须
使用可验证的 NVS 事务顺序，并在后续启动时检查完整性。如果恢复写入中途掉电，下一次启动
应保持旧认证状态或完整的恢复状态，不能进入无密码保护的中间状态。

认证恢复只重置：

- 密码盐和密码派生值；
- 首次设置完成标志；
- 登录失败锁定状态；
- RAM 中的 Token、认证会话和打印会话；
- 恢复设置临时状态。

认证恢复不得清除或修改：

- eFuse `device_id` 和出厂 MAC；
- 设备 TLS 私钥、证书和服务器绑定关系；
- 每机恢复码验证值；
- Secure Boot、Flash Encryption 和其他安全 eFuse；
- 当前固件、OTA 回滚信息和已验证打印机注册表；
- `credential_reset_counter` 和必要的恢复审计记录。

第一版不向普通用户提供“擦除全部 Flash”的完全恢复出厂功能。售后服务工具可以清理允许
恢复的配置分区，但即使执行服务级恢复，也永远不能改变 eFuse `device_id`。服务器在下一次
连接时根据不变的 `device_id` 识别原设备，并记录恢复计数发生变化。

## 10. 管理页面

页面作为压缩静态资源内嵌固件，第一版包含：

- 登录；
- 首次强制修改密码；
- 板卡状态；
- 打印机身份、命令集和连接状态；
- 当前会话和页码进度；
- 选择单页 PRN 并上传打印；
- 上传和 USB 发送进度；
- 修改管理密码；
- 展示启动恢复结果、恢复码认领和恢复窗口倒计时；
- 空闲时重启设备。

页面不提供下载或浏览 PRN 内容的能力。服务器是主要生产调用方，网页主要用于安装、诊断
和人工测试；网页调用与服务器调用必须使用同一套 API 和状态机。

## 11. 错误码基线

| 错误码 | 含义 |
|---|---|
| `AUTH_REQUIRED` | 缺少或无效 Token |
| `PASSWORD_CHANGE_REQUIRED` | 首次设置尚未完成 |
| `DEVICE_UNPROVISIONED` | eFuse 编号、CRC、写保护或证书绑定校验失败，禁止生产业务 |
| `RECOVERY_CLAIM_REQUIRED` | 首次设置或恢复改密尚未完成恢复码认领 |
| `RECOVERY_CLAIM_INVALID` | 恢复 claim 无效、过期或不属于当前认证会话 |
| `RATE_LIMITED` | 登录或请求频率过高 |
| `PRINTER_NOT_CONNECTED` | 未连接打印机 |
| `PRINTER_UNSUPPORTED` | 当前打印机协议不在支持范围 |
| `PRINTER_NOT_VERIFIED` | 当前打印机未达到量产自动打印验证等级 |
| `PRINTER_NOT_READY` | 缺纸、未选中或报告错误 |
| `PRINTER_RESERVED` | 打印机被其他会话锁定 |
| `PRINTER_CHANGED` | 会话期间打印机身份发生变化 |
| `PRINTER_PROFILE_MISMATCH` | PRN 配置与当前打印机不匹配 |
| `SESSION_NOT_FOUND` | 会话不存在或已过期 |
| `SESSION_OWNER_MISMATCH` | 当前认证会话不是打印会话所有者 |
| `PAGE_OUT_OF_ORDER` | 页码不是期望的下一页 |
| `PAGE_NOT_READY` | 上一页尚未达到允许提交下一页的状态 |
| `UPLOAD_IN_PROGRESS` | 相同页面正在接收，未再次入队 |
| `PAGE_CONFLICT` | 相同页码被不同内容摘要占用 |
| `PAGE_TOO_LARGE` | 页面超过 2 MiB |
| `PAGE_LENGTH_MISMATCH` | 实际长度与声明不一致 |
| `PAGE_HASH_MISMATCH` | SHA-256 校验失败 |
| `INSUFFICIENT_MEMORY` | 无法分配页面缓冲 |
| `USB_TRANSFER_FAILED` | USB 发送明确失败且未完整交付 |
| `PRINT_RESULT_UNKNOWN` | USB 中途异常，可能已经打印部分内容 |
| `DEVICE_BUSY` | 当前状态不允许重启或修改关键配置 |

## 12. 开发阶段

### 阶段 0：基线保护与测试准备

- 保留当前 HP 2300 实机通过的版本和日志作为回归基线；
- 建立开发配置与量产配置；
- 增加构建版本、设备 ID 和统一日志字段；
- 评审 ESP32-S3 eFuse 总体分配，预留编号区域且不与安全密钥、Custom MAC 冲突；
- 定义制造工具的 `--device-id` 参数、恢复码生成与标签流程、服务器预留接口和失败隔离流程；
- 准备至少一台 HP 2300 和若干不同协议/厂商打印机测试样本。

完成标准：现有 HP 测试 PRN 仍能通过独立回归程序正常打印，并形成第一批打印机支持矩阵；
除 HP DeskJet 2300 外，未进入矩阵的型号不作为第一版兼容承诺；eFuse 分配表和制造编号
格式通过评审。

### 阶段 1：USB 传输层重构

- 删除固件内嵌 `1.prn` 的运行时依赖；
- 将 USB 生命周期、枚举、状态和发送拆分为可重复调用模块；
- 将阻塞死循环改为显式状态机和错误返回；
- 支持从调用方缓冲区发送任意长度页面；
- 实现断开、STALL、超时和短传输处理；
- 保证错误后不自动重放可能已经部分发送的页面。

完成标准：连续打印多份不同内存缓冲页面，无需重启板卡。

### 阶段 2：通用打印机发现

- 动态遍历 Printer Class 接口和 Bulk 端点；
- 支持 Protocol 1/2；
- 读取 USB 字符串、`GET_DEVICE_ID` 和 `GET_PORT_STATUS`；
- 生成打印机信息 JSON 模型和稳定指纹；
- 建立已验证打印机注册表。

完成标准：HP 2300 不再依赖硬编码接口和端点；未知协议设备被明确拒绝而不是盲目发送。

### 阶段 3：PSRAM、网络和基础 API

- 正确启用并验证 8 MB PSRAM；
- 配置 SoftAP、静态 IP 和 DHCP；
- 启动 HTTP Server；
- 实现统一 JSON 和错误码；
- 实现板卡状态、打印机信息和打印机状态接口；
- 加入 2 MiB 请求上限和分块接收框架。

完成标准：多个客户端可同时查询，2 MiB 数据接收不会耗尽内部 RAM 或触发看门狗。

### 阶段 4：认证和首次改密

- NVS 保存密码验证数据和首次设置标志；
- 登录、注销、Token 刷新、过期和失败限速；
- 首次设置未完成时签发受限 Token；
- 强制改密和全 Token 吊销；
- 实现启动阶段 GPIO 连续高电平检测、选择性认证清除、等待 GPIO 释放和恢复计数；
- 实现每机恢复码、一次性 challenge、独占 claim 和认证会话绑定；
- 实现管理页面的登录与改密流程。

完成标准：初始密码只能进入设置流程，改密后旧密码和旧 Token 均不可使用；并发改密只有
一个请求成功，掉电后 NVS 中的密码状态保持旧值或完整新值，不出现半写入状态；认证恢复
不改变 `device_id`、设备证书和服务器绑定。

### 阶段 5：会话锁和逐页打印

- 创建、查询、心跳、自动结束和取消会话；
- 绑定认证会话和打印机指纹；
- PSRAM 单页缓冲、Content-Length 和 SHA-256 校验；
- 连续页码和总页数检查；
- 页面完成、失败和结果未知状态；
- 多客户端互斥和安全租约释放；
- 页面去重和最小幂等控制。

完成标准：至少 4 个 Wi-Fi 客户端同时连接和查询时，始终只有一个会话可打印；当前会话
逐页完成前其他客户端不能插入。2 MiB 页面在 15 秒内完成网络接收（正常近距离无线环境），
并在 500 次页面缓冲分配/释放循环后无内存泄漏，内部 RAM 最低剩余量不低于 80 KiB。

### 阶段 6：网页、诊断和稳定性

- 完成状态和人工上传页面；
- 完成日志脱敏、请求 ID 和关键性能指标；
- 增加堆低水位、PSRAM 最大块和任务看门狗监控；
- 完成断网、断 USB、缺纸、换打印机、重复请求和超时测试；
- 进行长时间、多页和多客户端压力测试。

完成标准：连续运行和故障注入测试无崩溃、无跨用户插页、无自动重复打印。

### 阶段 7：产品化安全与 OTA（正式交付前必须完成）

- 定制 16 MB 分区表和双 OTA；
- HTTPS 和证书信任方案；
- 签名 OTA、回滚和断电恢复；
- Secure Boot v2、Flash Encryption Release 模式样机验证并在量产配置中启用；
- 物理恢复和首次初始化流程；
- 量产编号写入、读回、写保护、证书绑定、恢复码交付、服务器登记和失败隔离；
- 量产烧录、密钥保管和设备身份方案。

完成标准：安全样机能完成生产烧录、HTTPS 调用、首次设置、签名升级、失败回滚和物理授权
恢复；量产配置启用 Secure Boot v2 和 Flash Encryption Release 模式并通过专项评审。未完成本阶段
只能作为工程测试版本，不能作为正式产品交付。

## 13. 测试与验收

### 13.1 功能测试

- SoftAP 名称、密码、IP 和 DHCP 符合配置；
- 多个客户端能同时连接并查询；
- 首次设置未完成时必须改密；
- 每块板卡返回烧录时分配且写保护的唯一 `device_id`；
- 查询接口返回真实板卡和打印机信息；
- 服务器能依据返回信息选择正确驱动；
- 1 字节、1 MB、2 MiB 页面边界正确；
- 超过 2 MiB 在读取正文前尽早拒绝；
- 多页按顺序打印，不能越页或插页；
- 会话结束后下一用户才能获得打印权。

### 13.2 故障测试

- 上传前、上传中和上传完成后断开 Wi-Fi；
- USB 发送前、发送中和发送后拔掉打印机；
- 打印期间缺纸、开盖和打印机报错；
- 当前用户停止心跳；
- 第二用户持续竞争；
- 打印机中途被换成相同或不同型号；
- 页面长度不符、摘要错误、重复页和错误页码；
- PSRAM 分配失败和内部 RAM 低水位；
- 上传、打印和空闲状态下重启或掉电。
- eFuse 编号为空、CRC 错误和写保护状态异常；
- 恢复码 KDF 参数/验证值缺失、损坏和量产读回自检失败；
- 设备证书 ID 或公钥指纹与 eFuse/制造登记不一致；
- 恢复 GPIO 正常低电平、短暂高电平毛刺、持续高电平、浮空、卡在高电平和恢复写入中掉电；
- GPIO 持续高电平达到确认时间后必须恢复认证，未达到确认时间不得恢复；GPIO 未回到低电平
  前不得启动 SoftAP 和网页；
- 认证恢复后旧密码、旧 Token 失效，新密码设置必须完成恢复码 claim；
- 多客户端同时使用统一初始密码时，只有恢复码 claim 所属认证会话可以设置新密码；
- 认证恢复前后 `device_id`、证书和服务器绑定保持不变。

### 13.3 性能与稳定性测试

- 2 MiB 页面接收期间内部 RAM 保持安全余量；
- 连续多页后无显著内存泄漏或最大连续块持续下降；
- 多客户端查询不影响 USB 发送；
- 工程验收至少连续运行 72 小时；打印链路至少完成 500 页等价数据传输，其中实际纸张
  测试页数由耗材条件确定，其余可使用经过验证的 USB 测试设备或测试模式；
- Wi-Fi、HTTP/HTTPS 和 USB 任务不触发看门狗；
- Flash 写入量符合寿命设计，不把 PRN 页面写入普通配置分区。

### 13.4 打印机兼容性测试

每个受支持型号记录：

- 厂商、型号、VID/PID、序列号行为；
- Interface、Protocol、端点；
- 完整 IEEE 1284 Device ID；
- 使用的操作系统驱动和版本；
- 驱动生成的打印语言；
- 一页及多页实际出纸结果；
- 缺纸、断线、取消和恢复表现；
- 已知限制。

只有完成上述测试的型号才能标记为 `verified_supported`。第一版必验型号为
HP DeskJet 2300（`03f0:3654`）；其他型号清单必须在阶段 0 结束前写入本节或独立支持矩阵。
在清单确定并验收前，除 HP DeskJet 2300 外只能声明“可发现”或“待验证”，不能承诺支持。

## 14. 主要风险和应对

| 风险 | 应对 |
|---|---|
| 无法通用判断机械出纸完成 | 公开使用 `usb_delivered` 语义，型号专用能力单独扩展 |
| PRN 与打印机不匹配 | 打印机信息接口、服务器配置映射、会话指纹和 profile 校验 |
| 网络断开产生半页 | 整页先缓存在 PSRAM，完整校验后才发送 USB |
| USB 中途失败导致结果不确定 | 禁止自动重试，返回 `PRINT_RESULT_UNKNOWN` |
| 多用户作业穿插 | 单活动会话、所有者绑定、连续页码和租约状态机 |
| PSRAM 碎片或不足 | 固定单页上限、显式能力分配、运行时最大块检查和压力测试 |
| Flash 磨损 | 普通 PRN 不落 Flash，只持久化少量配置和安全数据 |
| 通用打印机范围被高估 | 明确协议边界，建立逐型号验证注册表 |
| 统一初始密码被抢先使用 | 首次改密必须通过每机唯一恢复码、一次性 challenge 和认证会话绑定 |
| HTTP 泄露凭据和文档 | 研发阶段隔离使用，量产阶段实施 HTTPS 和证书信任方案 |
| Secure Boot/加密配置不可逆 | 专用样机和量产流程验证后再烧写 eFuse |
| 编号重复或 eFuse 错烧不可撤销 | 服务器先预留、完整映像一次烧写、读回校验、写保护和失败板隔离 |
| 恢复功能被远程滥用 | 恢复只在启动 GPIO 持续高电平时触发，设置新密码仍需每机唯一恢复码 claim |
| 攻击者伪造 JSON 中的设备编号 | 服务器同时校验产品 CA、证书内 ID 和制造登记公钥指纹 |

## 15. 尚待实施阶段确认的参数

## 16. 第一版交付定义

第一版可交付版本至少满足：

- 板卡未初始化时启动 `mybips.com` SoftAP；首次设置可配置本机热点名称和密码，
  重启后按保存的配置启动，并始终在 `192.168.188.1` 提供服务；
- 每块板卡具有量产参数写入、可读且写保护的唯一 `device_id`；身份有效时所有 JSON 响应
  均携带该 ID，身份无效的诊断响应只返回 `device_id: null`；
- 多客户端可连接、登录和查询；
- 初始密码 `mybips.com` 在首次设置流程中必须修改；
- 首次设置和认证恢复后的改密必须通过每机唯一恢复码 claim；
- 返回可用于服务器选择驱动的完整打印机信息；
- 支持标准 USB Printer Class Protocol 1/2 的动态发现；
- 单活动会话独占打印机；
- 客户端声明总页数并按顺序逐页上传；
- 单页最大 2 MiB，整页在 PSRAM 完整校验后立即打印；
- 上一页达到 `usb_delivered` 后才接受下一页；
- 错误状态不会自动重放可能已经部分打印的页面；
- 提供基础管理页面、板卡重启和密码修改；
- 提供启动 GPIO 高电平触发、且不会改变设备 ID、证书和服务器绑定的认证恢复功能；
- 服务器验证设备证书、eFuse ID 和制造登记公钥指纹的一致性，不把 JSON ID 当作认证凭据；
- HP DeskJet 2300 保持回归通过；其他型号只有进入支持矩阵并验收后才对外声明支持；
- 正式交付版本完成阶段 7 的 HTTPS、签名 OTA、恢复流程和安全配置验收。
